# 视觉设计

> 记录日期：2026-10-16
>
> 责任角色：Director
>
> 状态：新版设计约定，实际效果以页面检查结果为准。

新版围绕“每个人的AI，都有自己的工作空间。”组织首页。先让访客看见产品怎样工作，再进入产品、架构、操作手册和开发对接。用户已否决旧绿色方案和过于简单的首页；这次同时调整配色、主视觉和内容节奏。

设计参考[Anthropic的frontend-design指导](https://github.com/anthropics/skills/tree/main/skills/frontend-design)：用真实内容决定视觉重点，让结构表达关系，控制装饰和自动动画。它提供设计方法，不作为照搬其它网站的模板。

## 颜色与字体

|用途|颜色|使用方式|
|---|---|---|
|海军蓝|`#071c48`|首页主视觉、重要深色区块和稳定的品牌底色|
|钴蓝|`#335cff`|主要按钮、选中项和重点连接|
|冷白|`#f8faff`|阅读背景与浅色区块|
|冰蓝|`#93c9ff`|深色背景上的辅助关系与局部强调|
|墨字|`#101e3c`|浅色背景上的标题与正文|
|次字|`#61708e`|摘要、说明和次要信息|

字体顺序采用`Avenir Next`、`PingFang SC`（苹方）、`Microsoft YaHei`（微软雅黑）及系统无衬线字体，不外链字体，离线仍能阅读。标题通过字号、字重和断行形成层次；正文保持舒适行长与行距。避免每段上方重复英文装饰标签，也不把每个标题中的一个词单独染色。

## 首页怎样展开

主视觉以真实产品截图为主体，结合工作空间边界和对话、文件、技能、业务系统的关系，形成前后层次。截图用于展示可辨认的产品，关系图用于解释它们怎样连接；阴影和透视只辅助层次。标题为“每个人的AI，都有自己的工作空间。”，行动入口明确指向认识产品和开始使用。截图继续注明真实界面、合成教学数据，不把演示状态当作业务成绩。

页面按下面的内容推进，使用长短区块和深浅背景交替，避免整页都是等大的圆角卡片：

1. 用海军蓝主视觉建立第一印象，让工作空间与产品界面同时出现。
2. 紧接真实工作场景，切换查看周报、技能和业务面板。
3. 用不等大的内容区解释持久空间、Skill与工具、员工身份与业务授权的关系。文件树和能力图承担说明，不显示虚构的实时数据。
4. 用深色架构区块展开控制、执行、模型和业务访问的分工，提供继续阅读入口。
5. 回到浅色阅读区，用两本手册封面和开发接口入口，分别引导员工、管理员和开发者。
6. 补充设计文章和入门路线，保留产品适用范围说明。

不添加未经证实的客户标识、使用人数、效率提升比例或成功案例。场景文案解释当前能力与边界，不替真实部署承诺结果。

## 正文与交互

正文页以阅读为主，首页的大幅视觉不延续到每一章。保留搜索、章节导航、本页目录、前后篇、图片放大和明暗主题。截图缩略图应能看清主要区域，放大后能检查具体字段；代码和宽表格在自己的区域内滚动。

主要交互提供可见的键盘焦点。搜索和图片弹层应能用键盘进入、关闭并回到原位置。手机页面收起次要导航，保留清楚的返回和目录入口，避免截图、表格或标题把整页撑宽。自动动画只用于建立主视觉层次，响应系统的减少动画偏好；内容不能依赖动画结束才可见。暗色主题重新检查文字与背景的搭配，不直接反转截图颜色。

## 为什么这样改，怎样检查

旧方案的问题由用户反馈明确：绿色不符合期待，首页过简，产品特点没有充分展开。新版以蓝色形成稳定基调，用真实界面让访客认识产品，以工作空间关系解释区别；深浅与长短区块承担内容分组，阅读区保持克制。这些是改版理由，不等于效果已经得到验证。

页面完成后检查：桌面第一屏是否看清标题和产品；场景切换是否同步更新；关系图与架构是否表达真实分工；手机是否有横向溢出；明暗主题下文字、按钮和焦点是否清楚；搜索、目录、前后篇与图片放大是否可用；减少动画时内容是否完整。自动检查与人工截图复核结果另行记录，未检查的项目不标为通过。
