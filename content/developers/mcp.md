# 将MCP工具接入蜂巢

MCP让智能体发现远程服务提供的工具并发起调用。适合已经有稳定工具接口、希望同时供Hive Pi和OpenCode使用的场景。若工作主要由一段脚本、模板和处理步骤组成，也可以先使用[Skill](/docs/developers/skills/)。

当前蜂巢接入远程只读Streamable HTTP MCP，不提供旧式HTTP+SSE回退。只读必须由目标服务或服务账号实际限制，工具注解和“请不要修改”的提示不能代替权限。

## 1.准备服务

服务开发者应准备可被员工运行环境访问的HTTP或HTTPS地址，支持MCP初始化、工具发现和调用。工具名称、用途、输入与输出要能让调用者理解；服务返回的文本是数据，不能借工具说明要求扩大权限。

接入前至少完成以下检查：

- 服务或账号只允许读取数据，不提供可被误用的写权限。
- 认证失败明确拒绝，不自动降级为匿名或切换其它账号。
- 工具返回结构和业务错误稳定，不回显请求凭据或调试堆栈。
- 能在当前5秒初始化、发现和单次调用限制内完成必要操作。

MCP地址不能包含URL用户名、密码、查询参数或片段。固定Token填写到独立认证字段，不能放在URL里。

## 2.选择认证方式

|方式|适合情况|业务方需要做什么|
|---|---|---|
|无认证|业务方明确允许匿名读取的数据|服务自己控制匿名能力与访问范围|
|固定Token|服务使用独立只读服务账号|提供Token，由管理员安全填写；服务端检查权限|
|蜂巢身份|需要按当前蜂巢员工映射业务账号和权限|服务绑定一个业务系统，网关在线核验该系统短期Token|

蜂巢身份模式必须关联单个启用、且已配置启用统一身份客户端的业务系统。员工同时需要该系统资格和MCP资源分配。通用或多系统MCP使用无认证或固定Token方式。

蜂巢身份复用[业务身份](/docs/developers/identity/)的取Token与在线核验，不增加OAuth授权页面或长期刷新凭据。业务网关继续以`issuer/sub`关联业务用户，按当前业务权限处理工具请求。不要要求模型或员工手动向工具参数传Token。

## 3.管理员登记并分配

1. 在管理控制台进入“MCP管理”，点击“新增MCP”。
2. 填写名称、用途、标签、地址及适用业务系统，选择认证方式。
3. 固定Token模式填入Token；蜂巢身份模式选择对应单个业务系统。
4. 保存配置，再按下节验证连接和业务调用。
5. 在用户能力分配中给测试员工分配这个MCP；限定系统的服务还要分配匹配系统资格。

管理员维护唯一当前配置，没有草稿发布、历史版本或管理员启停开关。保存只检查配置，不自动连接服务。固定Token加密保存且不回显；编辑留空保留已有值，切换为无认证或蜂巢身份会清除原固定Token。

目标地址不能在原服务ID上修改。更换目标时创建新的MCP服务并重新分配，避免旧授权被悄悄用于另一个服务。

## 4.区分连接测试与实际任务

无认证或固定Token服务可点击“测试连接”。测试在隔离环境中完成初始化和工具发现，5秒总时限，不请求模型、不调用业务工具。成功说明当时能连接和发现工具，不证明业务结果正确、账号确实只读或员工运行环境必然可达。

蜂巢身份模式没有管理员连接测试。管理员没有员工运行身份，不能伪造员工或匿名探测。应使用已获授权员工的任务完成验证：

1. 员工在“个人设置→系统工具”查看服务，确认本人未停用且业务范围匹配。
2. 新建对话，选择可用的Hive Pi或OpenCode，在“添加文件与工具”中指定该MCP。
3. 提交明确的只读查询，检查工具调用记录、业务结果和最终任务状态。
4. 验证未关联、无权限、身份过期和撤权时明确失败，没有退回匿名或固定身份。

聊天中指定MCP只表达本轮使用意图，不授予权限，也不代表其它可用工具全部被撤销。每次任务最多16个MCP，超限明确拒绝。

## 5.配置变化的影响

仅修改标签，或实际相同的配置重复保存，不会停止员工任务。仅名称和用途变化推进普通同步，当前任务可能保留旧说明。

认证、访问范围、人员分配、员工个人启停、相关系统资格等实际变化会使当前配置失效，停止旧运行环境并同步，活动任务可能中断；删除MCP也有这一影响。需要维护时先理解受影响员工和任务，不把修改理解为对当前执行无影响的目录编辑。

目录中的最近测试结果不是实时健康状态。出现连接失败时检查服务协议、网络、认证方式和业务权限，见[接入排查](/docs/developers/troubleshooting/)。
