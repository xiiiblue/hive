## 1.先从一件真实工作认识蜂巢

假设运营人员要做一份工单周报。过去，他需要登录工单系统、找出本周记录、核对负责人和状态，再整理成报告。蜂巢允许他把任务交给智能体：智能体根据任务要求，读取已授权的系统和工具，在员工自己的工作空间中处理资料并生成结果。

这件事需要的不只是一个聊天框。平台必须知道“谁提出任务”“他有权使用什么系统”“应该遵守哪些要求”“谁来执行”“用哪个模型”“文件放在哪里”“执行失败后怎样查”。控制台的菜单正是围绕这些问题设置的。

![蜂巢管理对象关系：人员、能力、执行与管理记录](/media/manuals/admin/01-concepts.svg)

图中每组回答一个问题。管理员先配置人员、能力和执行条件，员工才能开展工作；管理记录帮助追溯结果和处理故障。箭头表示使用关系，不表示所有配置必须一次完成。

## 2.这些名称分别指什么

|名称|用普通话理解|为什么要单独管理|
|---|---|---|
|平台管理员|进入本控制台，维护账号、企业能力和平台运行的人|管理员能影响全平台，需要与实际处理工作的员工身份分开|
|员工|在员工工作台中提问、处理任务并拥有个人资产的人|任务、用量、工作文件和能力分配需要归到具体员工|
|部门|员工目录中的组织归类|便于找人、筛选和统计；归入部门不自动获得业务系统权限|
|业务系统|企业已有的工单、项目、日志等系统在蜂巢中的登记项|集中维护系统名称、公共信息和使用人员，给关联能力一个明确的适用范围|
|企业Skill|管理员维护的一份任务做法、说明和配套文件，Skill意为技能|让不同员工重复使用同一种做法，发布更新时保留版本|
|业务面板|嵌入员工工作台的业务页面|把需要点选和查看的业务操作做成页面，不必每次通过聊天描述|
|MCP服务|按Model Context Protocol提供工具的服务，任务可以发现和调用它的工具|Skill可以说明“怎么做”，MCP提供可调用的工具；两者可分别配置和授权|
|工作规范|对一批员工任务共同提出的要求|把“先核实数据、不要泄露客户资料”等要求集中维护，不必每次提问都重复输入|
|执行引擎|把任务交给模型、调工具并持续推进工作的程序，界面目前展示Hive Pi和OpenCode|执行方式和支持的能力可能不同，模型也要与引擎兼容|
|模型服务与模型|前者是提供模型的上游连接，后者是上游连接中可选用的具体模型|同一服务可能提供多个模型，它们的能力、时限、价格和适用引擎不同|
|工作空间／运行环境|工作空间保存员工资产；运行环境是实际执行程序的容器，界面有时保留Workspace和Runtime名称|保存文件与启动程序是两件事，程序停止不等于员工文件被删除|
|任务／模型调用|任务是一项员工工作；模型调用是执行中向模型发出的一次请求|一个任务可能多次请求模型，排查和计费不能只数聊天消息|

**账号能登录，不代表它已经获得业务能力。**员工使用某个系统通常需要系统使用资格；关联的企业Skill、面板和MCP还要按需要分别分配。发布资源也不等于分配人员。操作顺序见[第03章](/docs/admin/03-capabilities-and-rules/)和[第10章](/docs/admin/10-admin-workflows/)。

## 3.进入管理员控制台

先向平台维护人员取得本部署的访问地址、管理员登录名和初始密码。管理员页面使用`/admin/`路径；员工工作台是另一个入口。示例地址可理解为`https://你的蜂巢地址/admin/`，实际协议与域名以所在环境为准。

![管理员登录页](/media/manuals/admin/01-login.png)

图中中间的登录框只接受管理员身份，员工账号应前往员工工作台。

1. 打开管理员入口，在“登录名”和“密码”中输入分配的账号信息。
2. 点击“进入管理控制台”。
3. 如果出现“设置新密码”，说明首次登录或密码刚被重置。输入8至128位、同时包含大写字母、小写字母和数字的新密码，点击“保存并进入控制台”。
4. 成功后进入“平台概览”，左下角应显示自己的管理员名称和登录名。

初始密码由部署和账号管理方式决定，创建账号表单不要求管理员手工设置。不要从截图、旧记录或其它环境猜密码。没有管理员账号时，请联系维护人员创建；登录页没有公开注册入口。

如果提示账号或密码未通过验证，核对是否进错入口、账号是否停用及输入是否准确。失败次数过多可能暂时锁定，应按提示稍后再试。遇到“无法连接服务”先检查地址、网络及服务是否可访问，不连续尝试重置密码。

## 4.怎样找到一个功能

左侧导航按五个问题分组：

|分组|主要用途|
|---|---|
|组织与人员|创建员工、归入部门、分配能力和工作规范|
|企业能力|登记业务系统，维护企业Skill、市场Skill、MCP和业务面板|
|模型与用量|查看执行引擎，配置模型服务，核对调用、用量和费用|
|集成与接入|配置业务网站使用蜂巢身份登录，管理其它程序调用蜂巢的API Key|
|运行与维护|查任务和员工环境，处理异常，管理备份、导出和审计|

“平台概览”位于各分组之前。点击对象名称或“管理”等入口通常进入详情；返回箭头可回到相应列表。手机或窄窗口下，用左上角按钮打开导航抽屉；选中页面后抽屉收起。表格过宽时在表格内部横向滚动，不要把屏幕外的操作误认为消失。

筛选后的列表只代表当前筛选结果。找不到对象时先清除搜索、标签、发布状态或人员筛选，再判断是否停用、未发布或尚未分配。“刷新”会重新读取状态；保存后仍应查看对象的当前状态，不能只凭按钮点击就判断完成。

部分页面会在离开时保护未保存的修改。出现提示时，选择继续编辑并保存，或者明确放弃；不要用刷新页面来解决尚未核对的保存失败。

## 5.平台概览应该怎么看

![平台概览：状态、资源、待处理事项和基础服务](/media/manuals/admin/01-overview.png)

页面上方先看“平台状态”“运行中任务”“排队中任务”和“新任务启动”。下方四张资源卡片通往账号、业务系统、工作空间和公共Skill；“待处理事项”把需要进一步查看的问题汇集到一起。右侧基础服务可以展开说明，异常项会显示检测结果。

1. 先确认“新任务启动”是否允许；若已暂停，去“平台运行”看操作原因。
2. 查看“待处理事项”，从事项链接进入具体页面。账号待首次改密是待办，不等同于服务故障。
3. 查看基础服务的状态、检测时间和说明。未取得、未知、未启用与正常含义不同；不要把没有报错当作已验证正常。
4. 看到备份失败数量时，进入“备份与恢复”核对时间和失败原因。历史失败数量不能直接说明最新恢复点不可用，也不能证明当前数据已经安全备份。

概览提供入口和摘要，具体处置仍在相应页面完成。检测正常只说明已检测项目当时的结果，不代表每个外部业务操作都能成功。

## 6.维护自己的密码和退出

点击侧栏底部的“个人设置”，查看当前管理员的显示名称、登录名、账号类型和账号ID。

![个人设置与修改登录密码](/media/manuals/admin/01-account.png)

1. 在“修改登录密码”中输入当前密码、新密码和确认新密码。
2. 新密码需符合上面的长度和字符要求，不能与当前密码相同，两次输入必须一致。
3. 点击“保存新密码”。成功后表单清空，页面提示其它管理员登录会话已经失效；当前浏览器切换到新的登录会话，可以继续使用。

这里的“会话”指登录状态，不是员工聊天对话。密码泄露、人员离岗或使用共享电脑时，应及时修改密码或退出。

结束管理后点击侧栏底部“退出管理员登录”。如果当前页面有未保存的修改，先按提示处理；退出后应看到管理员登录页。后台请求提示登录失效并返回登录页时，重新登录，再读取最新对象状态后继续操作。
