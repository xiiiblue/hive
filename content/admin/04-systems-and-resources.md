员工想让蜂巢“查询照明告警”或“汇总工作日志”，除了会对话的智能体，还需要知道查哪个系统、怎样调用、谁有资格使用。本章把这些准备工作分成三个对象：业务系统说明“访问谁”，企业Skill说明“怎样做”，业务面板提供“从哪里操作”。

本章操作需要平台管理员账号。发布资源和分配人员会影响员工实际可用的能力；正式环境中的操作应按本单位已经确认的范围执行。

## 先分清三个对象

以照明业务为例：

|对象|它解决的问题|在控制台中填写什么|
|---|---|---|
|业务系统|蜂巢怎样区分照明系统与其它系统，哪些员工可以使用它|系统名称、公共属性、使用人员；需要时配置统一身份|
|企业Skill|智能体怎样按企业约定完成一类工作|包含操作说明和附属文件的Skill包，例如“查询告警并生成日报”|
|业务面板|员工怎样通过页面查看或操作业务|HTML页面及其说明文件，例如“照明运行总览”|

Skill是一组给智能体使用的说明和文件，可以包含步骤、脚本、参考材料。它不等于业务系统，也不会因为上传了Skill就自动给员工授予业务权限。业务面板是提供给员工使用的网页；上传页面也不代表业务接口已经接通。

![业务系统目录及关联能力](/media/manuals/admin/04-systems.png)

业务系统卡片会显示关联的Skill、面板和MCP数量，以及资源待发布情况。这里的数量用于了解配置；通用资源也会计入关联能力，不能据此判断某名员工已经获得这些资源。MCP是供智能体调用工具的服务，见[Skill市场与MCP](/docs/admin/05-skills-and-mcp/)。

## 登记和维护一个业务系统

### 新建系统

准备一个稳定的系统标识和便于员工理解的名称。例如标识用`lighting`，名称用“照明运维系统”。标识用于程序识别，创建后不能修改；名称用于界面展示，之后可以修改。

1. 在左侧“企业能力”中打开“业务系统”。
2. 点击“新建系统”；尚无系统时也可以点击“新建第一个系统”。
3. 填写“系统标识”“系统名称”，按需要填写“说明（可选）”。系统标识只能由1—32位英文小写字母组成，不能有数字、空格或连字符。
4. 点击“创建并进入”。

![新建业务系统](/media/manuals/admin/04-system-create.png)

成功后会进入该系统的“概览”。负责人初始使用创建者的显示名称，可通过“编辑资料”更正。创建只是登记目录项；后续仍要配置需要的公共属性、分配人员、准备资源，并验证业务访问。

如果提示系统标识已被使用，先返回目录检查是否已有同一系统。已有系统需要维护时，应进入原系统修改资料，不要为绕过重名提示重复登记。

### 查看概览和编辑资料

点击系统卡片后，“概览”列出系统标识、维护人、使用人数和网关鉴权状态。“网关鉴权”表示统一身份客户端是否配置和启用，不能代表真实业务联调结果。

1. 点击页面右上角“编辑资料”。
2. 在“系统资料”中修改“名称”“用途”“负责人”“联系方式”。名称和负责人必填。
3. 点击“保存资料”。弹窗关闭后核对页面上的名称、用途和维护人。

概览下方的“企业Skill”“业务面板”“MCP”是相应管理页入口，进入后仍需按资源名称和适用范围找到目标。

### 配置公共属性

公共属性是获准员工、Skill和面板共同读取的普通配置。例如同一系统的API入口地址可以用`api_base_url`保存，避免每份Skill都写一遍。它适合共享的地址、业务代号等信息；密码、Secret、Token等秘密不能放在这里。

![业务系统公共属性](/media/manuals/admin/04-system-properties.png)

1. 进入目标系统，选择“公共属性”。
2. 点击“添加属性”。
3. 填写“名称”“值”和可选的“说明”。例如名称填写`api_base_url`，值填写业务后端给出的完整地址，说明填写“照明业务API入口”。
4. 需要更多配置时继续添加；不再使用的属性点击该行“删除”。
5. 点击“保存公共属性”，看到“已保存。”后重新核对内容。

属性名称以英文小写字母开头，其后可使用英文小写字母、数字和下划线，最多64个字符，同一系统内不能重复。最多50项；值为字符串，每项最多4096字节，说明最多200个字符。`api_base_url`非空时需使用HTTP或HTTPS地址，不能夹带账号、查询参数、片段或通配符。

删除一行只是修改当前表单，点击“保存公共属性”才写入系统。保存后配置会同步给相关工作空间；仍需由获准员工验证实际业务访问，不能把“已保存”当作接口调用成功。

### 添加人员和撤销使用资格

把员工加到业务系统中，表示允许蜂巢为他提供该系统的使用资格。业务系统仍要把蜂巢身份与自己的业务账号关联，并按自己的规则检查具体业务权限。例如员工可以使用照明系统，不代表他有权查看所有项目。

1. 进入系统的“人员”页，查看当前已分配人员、账号状态和部门。
2. 点击“添加人员”。
3. 搜索姓名、登录名或部门，或者使用部门下拉框缩小范围。
4. 勾选要添加的员工。需要批量添加时，点击“选择当前筛选结果”；“清空选择”会取消本次全部勾选。
5. 核对已选择人数，点击“确认添加”。

![添加系统人员](/media/manuals/admin/04-system-people.png)

弹窗关闭后，员工应出现在人员表中并显示“已分配”。候选列表只显示账号可用且尚未分配的普通员工；停用系统不能新增人员。已有员工账号停用后，原分配会保留，员工恢复账号并重新登录后按当前分配使用。

撤销时，在对应员工行点击“撤销资格”，核对弹窗中的影响后点击“确认撤销”。撤销会使该员工的新访问被拒绝，正在执行的任务可能停止。成功后该员工从当前系统的人员表中移除。

系统使用资格与企业Skill、MCP的分配是分别管理的。需要让员工使用一项完整能力时，还应到“组织与人员→员工能力”核对资源分配；只在本页添加人员并不等于已经分配了所有Skill和工具。

### 停用与重新启用系统

业务停服或需要暂停接入时，可在系统详情右上角点击“停用系统”，核对影响后点击“确认”。停用会立即拒绝该系统的蜂巢身份并停止新的业务访问，相关员工工作空间和任务也可能受影响。它保留目录和分配记录，适合之后恢复使用。

恢复时点击“启用系统”并确认。成功后概览显示“系统已启用”。原分配员工可以重新取得身份，旧Token不会恢复，需要重新发起访问。

当前界面提供启用和停用，没有删除业务系统的按钮。

## 凭据应该在哪里管理

当前管理员控制台没有“凭据目录”页面，也没有为每个业务系统录入员工业务密码的表单。不要把旧材料中的凭据模板或接入配置步骤套用到本界面。

现在能在本章相关页面遇到的秘密各有用途：

|信息|当前管理入口|为什么不能混用|
|---|---|---|
|业务系统客户端Secret|“统一身份”中的客户端配置|由业务后端证明自己的客户端身份，不能给浏览器、Skill或面板|
|MCP固定Token|“MCP管理”中的“固定Token”认证|只用于连接指定MCP服务|
|开放API Key|“开放API”|允许外部程序以绑定员工的身份向蜂巢提交任务|
|业务系统自己的员工账号、密码和权限|各业务系统自己的账号管理功能|蜂巢配置不替代业务系统对账号关联和权限的管理|

相关操作见[统一身份与开放API](/docs/admin/07-identity-and-api/)和[Skill市场与MCP](/docs/admin/05-skills-and-mcp/)。

## 管理企业Skill

企业Skill适合由企业统一维护、需要管理员决定使用范围的能力。员工个人编写并分享的Skill在“Skill市场”管理，二者不是同一个发布入口。

### 从列表找到目标Skill

打开“企业Skill”。可以搜索名称、用途或标签，按标签和发布状态筛选。默认“当前资源”不显示已停用资源；需要恢复资源时改选“已停用”。“清除筛选”恢复默认条件，“刷新”重新读取数据，每页最多显示20项。

![企业Skill列表](/media/manuals/admin/04-skills.png)

卡片中的“已发布”表示有员工可使用的发布版本；“有待发布变更”表示已有发布版，同时另有新草稿；“尚未发布”表示还没有可用的发布版。点击名称或“管理Skill”进入详情。

### 上传第一个Skill

准备`SKILL.md`或仅包含一个明确Skill根目录的ZIP。`SKILL.md`顶部应包含名称和用途，最小示例如下：

```yaml
---
name: worklog
description: 查询和汇总工作日志
metadata:
  display_name: 工作日志助手
  example_prompt: 请汇总我本周的工作日志，按项目列出工时。
  tags: [工时, 项目管理]
---
```

`name`是稳定标识，只能使用小写英文字母、数字、点、下划线或连字符；`description`说明这份Skill的用途。正文继续写智能体完成任务需要遵守的步骤。中文名称和样例提示词可以写进`metadata`，也可以上传后在表单补充。

1. 在“企业Skill”页点击“上传企业Skill”。
2. 选择“适用业务系统（可选）”。留空表示通用，可以选择多个系统；适用范围决定这份Skill允许在哪些业务范围使用，不会自动替员工分配资源。
3. 点击文件选择区，选择`SKILL.md`或Skill ZIP。
4. 等待“已识别”结果，核对Skill标识、用途、文件数量，以及自动导入的中文名称、样例提示词和标签。
5. 补齐必填的“中文名称”和“样例提示词”，按需要调整标签。中文名称最多128个字符，样例最多2000个字符；标签最多20个，每个最多32个字符。
6. 点击“保存企业Skill”。

![上传并识别企业Skill](/media/manuals/admin/04-skill-upload.png)

保存后进入详情，只生成草稿，员工还不能使用这个新版本。文件最多15MB；单个解压文件最多2MB，解压总量最多10MB、512项。ZIP不能含不支持的路径或链接。系统会移除单层外目录，并在发布前重新检查。

如果提示同名资源已存在，进入原资源“上传新版”；不要把同一能力当作另一个资源重复创建。新版本中的稳定标识也应保持不变。

### 检查草稿并发布

![企业Skill详情和待发布版本](/media/manuals/admin/04-skill-detail.png)

1. 在详情顶部的“有一个待发布版本”区域点击“查看草稿”。
2. 在“文件与说明”中逐项点选文件，核对文本内容和版本号。可以通过“当前发布版”“待发布草稿”切换比较。图片等二进制文件不能在线预览，需下载后查看。
3. 需要调整时点击顶部“更新草稿文件”，上传完整的新文件并保存；确认无需此草稿时可点击“丢弃草稿”，它不会删除当前发布版或历史记录。
4. 确认内容后点击“发布此版本”。

![查看资源版本文件](/media/manuals/admin/04-resource-files.png)

发布成功后会提示“企业Skill新版本已发布”，概览的“当前发布版本”和卡片版本号应更新。发布只切换此Skill的文件内容，不替代业务系统连接配置或人员授权。还需在“员工能力”为目标员工选择资源，并通过实际任务检查它能否完成预期工作。

### 修改名称、样例、标签和范围

在详情“概览”点击“编辑Skill信息”，修改中文名称、样例提示词、适用业务系统或标签，点击“保存Skill信息”。这类信息保存后立即生效，不必重新发布文件。

适用范围不是一个只用于归类的标签。缩小范围会停止受影响员工的工作空间，正在运行的任务可能中断；重新启动后按新范围同步。只有展示用的标签不改变业务权限。

### 更新、下载和恢复历史内容

已发布Skill需要升级时点击“上传新版”；已有草稿时按钮显示“更新草稿文件”。上传不会立即替换发布版，保存后仍需检查并点击“发布此版本”。旧版文件中的中文名称、样例提示词和标签不会覆盖已维护的信息，这些信息应从“编辑Skill信息”调整。

![资源版本记录](/media/manuals/admin/04-resource-versions.png)

“版本记录”列出版本号、状态、用途说明和保存时间。对应行的操作分别是：

- “查看文件”：打开此版本的文件列表。
- “下载”：将此版本下载为ZIP；“概览”中的“下载版本”下载当前发布版。
- “恢复为新草稿”：把所选历史文件复制成一份新草稿，确认后还要发布才会生效。它不会恢复历史账号或人员权限。

### 暂停和恢复使用

可以在卡片右上角更多操作中选择“停用Skill”，或者在详情点击“停用”，核对影响后确认。停用后企业Skill不再提供给员工，历史版本和分配记录保留。同时，系统会停止所有已分配员工的运行环境，可能中断这些员工正在执行的其它任务，不限于正在使用这个Skill的任务。操作前先核对分配人员和任务安排。

恢复时，在“已停用”筛选中找到资源，选择“恢复使用”并确认。成功后原适用范围和员工分配重新生效；恢复不等于重新检查过实际业务接口。当前界面提供停用和恢复，没有永久删除企业Skill的入口。

## 管理业务面板

![业务面板目录：按系统和发布状态查找面板](/media/manuals/admin/04-panels.png)

业务面板让员工通过网页查看结果或完成操作，适合需要筛选、图表、表单和固定操作入口的场景。它可以和Skill服务同一业务系统，也可以作为通用页面，但仍需单独配置适用范围和员工分配。

### 查找和上传面板

打开“业务面板”。列表使用与企业Skill相同的卡片和发布状态，可以搜索名称、用途或标签文本，按所属系统和发布状态筛选；系统筛选也包含适用所有系统的通用面板。点击“管理面板”进入详情。

上传前准备HTML文件或只有一个HTML入口的面板ZIP。ZIP可以附带普通文件，但应保持页面依赖可访问。文件大小限制与企业Skill相同。

1. 点击“上传面板”，选择适用业务系统；留空表示通用。
2. 填写“面板名称”“面板标识（英文）”和“用途说明”。名称供员工查看；标识创建后不能修改，使用小写英文字母、数字、点、下划线或连字符，首位为字母或数字。
3. 选择HTML或面板ZIP，等待识别结果。
4. 展开“补充使用说明与API说明（ZIP已包含时可跳过）”，按需要补齐`PANEL.md使用说明`和`API说明JSON`。API说明需为有效JSON对象。
5. 点击“保存草稿”。

![上传业务面板](/media/manuals/admin/04-panel-upload.png)

`PANEL.md`用来说明页面用途和用法，`api.json`用来说明接口。上传包未提供时系统会补入默认文件；默认占位内容不能证明说明完整，发布前仍要在“文件与说明”核对内容、入口HTML和用途说明。

### 查看、预览和发布

面板详情同样分为“概览”“版本记录”“文件与说明”。查看草稿、丢弃草稿、发布此版本、上传新版、下载、恢复为新草稿的步骤与企业Skill相同。

![业务面板详情与页面预览](/media/manuals/admin/04-panel-detail.png)

面板存在发布版本后，在“概览”的“当前发布版本”中点击“页面预览”。预览针对当前发布版，会执行页面脚本和加载远程资源，但不会注入任何员工的业务连接参数。可以用它检查布局和静态交互；真实数据读取、业务权限和操作结果仍应由获准员工在工作台验证。“关闭预览”或“收起页面预览”可关闭。

发布后，所有适用系统统一使用这份面板的当前发布版本。进入“概览→编辑面板信息”可以修改面板名称和适用范围，点击“保存面板信息”后立即生效；文件内容和用途说明的修改从“上传新版”进入。

停用时使用卡片中的“停用面板”或详情中的“停用”。员工将不能继续打开该企业面板，基于它创建的个人面板也暂时不能使用；历史版本、个人修改和分配记录仍会保留。恢复使用后，原范围和分配重新生效。

## 遇到问题先核对这些事实

|现象|核对和处理|
|---|---|
|保存提示已被其他管理员修改|刷新当前对象，核对最新内容后再编辑；不要反复提交旧表单|
|添加人员找不到员工|检查账号是否可用、是否普通员工、是否已经分配，以及当前搜索和部门筛选|
|资源保存成功但员工看不到|检查是否已发布、资源是否停用、业务系统是否可用、适用范围和员工能力分配是否相符|
|ZIP无法识别或保存|检查是否只有一个Skill根目录或一个HTML入口，路径和文件大小是否合规；按页面错误修改原包后重传|
|新版无法保存，提示标识不可修改|保持原Skill的`name`或原面板标识，若确为另一能力则新建资源|
|面板预览正常，但业务请求失败|预览不带员工连接参数，继续检查员工系统资格、统一身份、业务账号关联和业务系统权限|
|页面提示需要平台管理员权限|使用具有平台管理员角色的管理账号；普通员工账号不能执行这些操作|
