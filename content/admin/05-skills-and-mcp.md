“企业Skill”“Skill市场”“MCP管理”都会影响智能体能做什么，但它们解决的问题不同。企业Skill由管理员统一维护；Skill市场让员工分享已经形成的工作方法；MCP让智能体连接外部工具。管理员需要分别检查内容来源、员工安装情况和工具接入范围。

本章操作需要平台管理员账号。员工在工作台发布、安装和使用Skill的步骤不属于管理员控制台；本章说明管理员能看到的版本、处置动作和MCP配置。

## Skill市场为什么按“版本”管理

一个Skill可以不断改进。员工发布的每个公共版本都有确定的内容、发布者和安装影响，管理员应针对出现问题的那个版本处置，而不是只看一个名称。比如“日报助手”的第一版存在错误，第二版已修正，处置时需要核对版本号和发布者，避免误停其它版本。

这里的“公共”指平台市场中可供员工发现和安装的版本，不代表已经公开到互联网。管理员页用于查看和处置员工发布版本，不提供管理员上传市场Skill、替员工安装或编辑市场文件的入口。企业统一维护的能力从[业务系统与企业资源](/docs/admin/04-systems-and-resources/)中的“企业Skill”进入。

![Skill市场管理列表](/media/manuals/admin/05-market.png)

打开左侧“企业能力→Skill市场”。页首三个数分别帮助判断当前查询范围内可分发版本数量、员工当前安装副本数量，以及还没有完成的紧急禁用数量。存在禁用失败时，页面会显示“存在未完成的紧急禁用”，说明仍有员工工作空间需要处理，不能仅凭版本状态已变成“紧急禁用”判断工作完成。

### 查询版本和查看详情

1. 在搜索框填写Skill名称或发布者登录名。
2. 按需要选择“可分发”“发布者已撤回”“已下架”或“紧急禁用”。
3. 点击“查询”。“重置”清除搜索、状态和失败项限制。
4. 点击目标版本行中的“查看”。

![Skill版本详情与禁用失败记录](/media/manuals/admin/05-market-detail.png)

详情列出发布者、发布时间、样例提示词、版本说明、外部系统声明、Root要求、安装数量和Publication ID。Root要求表示Skill声明是否需要运行环境中的系统最高权限，不表示管理员查看详情时已经给它授权；外部系统声明也是发布内容中的说明，不能代替实际接入和权限检查。

Publication ID是这一次公共发布的唯一编号。名称相近或处理失败时，可用它与审计记录对应。详情中的“当前安装”“累计安装”“已禁用安装”“待重试操作”应分别看待：累计安装不等于现在仍在使用，安装或卸载待重试也不等于紧急禁用失败。

|状态|它说明什么|已有员工安装副本|
|---|---|---|
|可分发|允许员工继续发现和安装此版本|按安装和员工使用状态提供|
|发布者已撤回|发布者停止新增安装|继续保留|
|已下架|管理员停止新增安装|继续保留|
|紧急禁用|管理员已要求停止使用受管理的安装副本|需要核对禁用是否全部完成|

### 下架一个版本

例如版本说明不完整、需要发布者修改内容，但不需要立即撤掉员工已有安装时，可以使用下架。

1. 核对Skill名称、版本号、发布者和“当前影响”。
2. 点击该行“治理操作→下架版本”。
3. 阅读弹窗中的现有安装数量和影响，填写操作原因，最多500字。
4. 点击“确认下架公共版本”。

成功后页面提示版本已下架，并显示审计事件编号；版本状态应更新为“已下架”。下架阻止新增安装，员工已有副本继续保留，所以它不适合用来处理必须立即停止使用的内容。

当前管理员页没有重新上架按钮。需要继续分发时，应由发布者按实际情况准备适当版本，不要把下架理解为一个随时可切换的展示开关。

### 紧急禁用和继续处理失败项

发现不应继续使用的公共版本时，可使用紧急禁用。系统会尝试把对应的受管理安装副本移出智能体能够发现的位置；已经从它复制出来的个人副本和正在运行的任务不会被撤回。因此，紧急禁用不是对所有复制内容和历史运行的一次全面删除。

1. 核对目标版本和当前安装数量。
2. 点击“治理操作→紧急禁用”。
3. 阅读影响，填写操作原因，点击“确认紧急禁用公共版本”。
4. 查看结果提示中的“已禁用”和“失败”数量，以及审计事件编号。
5. 如果有失败，点击“仅看失败项”或页首“仅看待处理版本”，找到仍待处理的版本。
6. 点击“查看”，在“禁用失败Workspace”中核对员工、工作空间编号和错误原因。Workspace就是该员工保存文件、安装Skill并运行任务的工作空间。
7. 处理对应工作空间的问题后关闭详情，点击版本行中的“重试失败”。每次重试产生新的审计事件。

成功判断要同时满足：版本状态为“紧急禁用”，失败数量降为0，页面没有此版本的待处理失败项。存在失败时，受影响工作空间的新任务会继续被阻止，直到禁用完成；不要为了让员工继续运行而忽略失败记录。

重试沿用原禁用决定，界面会直接处理失败安装项，不要求重新输入第一次的原因。若查询不到预期版本，先“重置”筛选再查；“仅看失败项”只在当前查询结果范围内筛选。

## MCP怎样把远程工具交给智能体

MCP（Model Context Protocol）是一种让智能体发现和调用工具的连接方式。例如业务后端提供“查询告警”工具，蜂巢连接服务后，智能体可以按任务需要调用它。Skill说明怎么完成工作，MCP提供执行中可调用的工具，二者可以配合使用。

当前控制台用于配置支持Streamable HTTP的远程只读MCP服务。它没有本地命令启动、标准输入输出连接等配置项。服务地址、认证方式、适用范围和员工分配都要准备好，保存一条连接并不会自动让所有员工使用。

![MCP管理列表](/media/manuals/admin/05-mcp.png)

列表显示名称、用途和标签、适用范围、认证方式和最近测试结果。可以搜索名称、用途、系统或标签，也可以按标签筛选；“刷新”重新读取列表，每页最多20项。

### 新增服务前准备什么

请向服务维护人员确认：

- 远程MCP的完整HTTP或HTTPS地址，以及服务是否支持Streamable HTTP。
- 服务采用无认证、固定Token还是蜂巢身份；后者还需要完成对应系统的统一身份接入。
- 服务提供哪些只读工具、适用哪个业务系统，以及应分配给哪些员工。

地址不能包含用户名、密码、查询参数或片段。不同地址代表不同授权对象，创建后不能直接修改；更换地址时要新增服务并重新分配员工。

### 新增无认证或固定Token服务

1. 打开“MCP管理”，点击“新增MCP”。
2. 填写“名称”“用途”，按需要添加标签。
3. 在“远程MCP地址”中填写服务地址。
4. 根据服务约定选择认证方式：“无认证”用于无需凭据的公开只读服务；“固定Token”使用服务提供的Bearer Token。
5. 选择“适用业务系统（可选）”，留空表示通用，可以选择多个系统。
6. 固定Token服务填写“Bearer Token”。
7. 点击“保存”。成功后列表出现服务，页面提示“MCP已创建，请为需要使用的员工分配。”

![编辑固定Token认证的MCP](/media/manuals/admin/05-mcp-edit.png)

Token只用于连接这一个MCP服务。编辑已有固定Token服务时，旧值不会回显；输入框留空表示保留原Token，填写新值表示替换。切换到“无认证”或“蜂巢身份”并保存后，会移除已保存的固定Token。

### 使用蜂巢身份连接业务工具

如果业务工具需要知道具体是哪名员工在请求，应使用“蜂巢身份”。蜂巢随MCP请求提供短期身份，网关在线核验后取得员工身份，再关联业务系统自己的账号和权限，避免让所有员工共用一份业务Token。

![使用蜂巢身份的MCP配置](/media/manuals/admin/05-mcp-hive.png)

1. 先在“业务系统”登记系统，并在[统一身份](/docs/admin/07-identity-and-api/)完成客户端配置和业务后端对接。
2. 新增MCP，填写名称、用途和远程地址。
3. 在“认证方式”中选择“蜂巢身份”。
4. 在“业务系统”中选择此MCP所属的一个系统。此模式必须且只能选择一个系统。
5. 点击“保存”。如果提示系统尚未启用统一身份，先完成接入配置。
6. 在“员工能力”中同时给目标员工分配该业务系统和此MCP。
7. 由已获授权员工发起包含该工具调用的实际任务，验证身份映射与业务权限。

此模式不用手工填写Token，短期Token到期后自动重新取得。“测试连接”按钮会禁用，最近测试显示“需员工任务验证”，因为管理员不能代替某名员工生成运行身份。

### 测试连接能证明什么

对“无认证”或“固定Token”服务，在列表点击“测试连接”。等待“正在连接并发现工具…”结束，查看结果和最近测试时间。

- “测试成功”表示连接、认证和工具发现成功，测试没有调用业务工具。
- “服务拒绝访问”通常需要核对认证配置及服务端权限。
- “测试超时”或“测试失败”需要核对远程服务、网络和验证服务状态。

连接测试不验证某名员工能否执行完整业务任务，也不代替目标系统权限检查。更改配置会清空旧测试结果，应按新的配置重新测试；蜂巢身份模式必须通过员工实际任务验证。

### 修改服务时先看任务影响

1. 点击目标服务行的“编辑”。系统会先重新读取配置和任务影响统计。
2. 按需要修改名称、用途、标签、认证或适用范围；远程地址为只读。
3. 核对保存影响。只改名称、用途或标签不会中断当前任务；修改认证、Token或适用范围会停止受影响员工的运行环境。
4. 如果出现确认框，查看已分配员工数、运行中任务数和排队任务数，点击“保存修改”。
5. 保存后核对列表和提示，按认证方式重新验证。

运行配置变化影响的是相关员工的整个运行环境：运行中的任务会中断，排队任务会取消，不限于正在使用此MCP的任务。影响数是查询时的快照，之后可能变化。暂未取得影响统计时页面会拒绝继续保存或删除，应刷新后核对。

若提示配置已被修改或删除，关闭编辑框并重新打开，按最新状态重新填写；不要继续使用旧表单。

### 删除服务

不再使用某个远程工具时，在该行点击“删除”。核对名称和员工、任务影响，点击确认框中的“删除”。成功后服务从列表移除，受影响员工的当前任务将中断，后续任务不能再使用此服务。

删除同样会停止相关员工的运行环境，不能把它理解为只清除一条列表记录。当前界面没有“恢复已删除MCP”入口；需要重新接入时应新建服务并重新分配。

## 常见问题

|现象|处理方式|
|---|---|
|MCP已创建，但员工不能使用|核对资源是否已在“员工能力”分给该员工、适用范围是否符合；蜂巢身份还需同时分配所属业务系统|
|不能保存蜂巢身份MCP|核对是否只选择一个业务系统，系统和身份客户端是否都已启用|
|编辑时没有显示原Token|这是正常表现，留空保留原值；只有确需更换时才填新值|
|想修改MCP地址却无法输入|地址不能直接修改；新增新地址的服务，重新分配并验证后再处理原服务|
|市场版本已紧急禁用，但仍有失败数|查看失败Workspace原因并继续重试；状态已改变不代表所有安装副本均处理完成|
|下架后员工仍能使用已安装Skill|下架只停止新增安装；需要停止受管理安装副本时评估紧急禁用|
|提示需要平台管理员权限|改用具有平台管理员角色的管理账号|
